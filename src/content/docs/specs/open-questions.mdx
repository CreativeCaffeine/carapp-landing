    <div class="spec-question__id">Q-VEHICLE<br/>-LIMIT</div>
    <div class="spec-question__body">
      <strong>車両台数制限を実装するか、LP 表記を変更するか</strong>
      <br/>
      LP / プラン画面では「Free: 1 台 / Premium: 無制限」と表記しているが、コード上は台数チェックなし。Free でも 2 台目を追加できる状態。
      <br/>
      <em>選択肢:</em> (a) 車両追加時に Free 制限チェックを実装 / (b) LP 表記を「将来制限予定」に変更 / (c) 制限自体を撤廃

## 🟡 中優先度（マーケティング/表記との整合）

<div class="spec-questions">
  <div class="spec-question" id="q-stats-diff">
    <div class="spec-question__id">Q-STATS<br/>-DIFF</div>
    <div class="spec-question__body">
      <strong>統計の Free/Premium 差分機能を具体化する</strong>
      <br/>
      LP 表記は「Free: 基本 / Premium: 詳細・期間比較」だが、実装上の差分は無し。Premium ならではの統計機能が定義されていない。
      <br/>
      <em>候補:</em> 期間比較（前月 vs 今月）、年単位の長期グラフ、車両比較（複数台ある場合）、CSV 取り込みでのトレンド分析など
    </div>
    <div class="spec-question__meta">
      <span class="spec-badge spec-badge--partial">🟡 中</span>
      <span>担当: PO + Designer</span>
      <span>状態: 未着手</span>

  <div class="spec-question" id="q-ads">
    <div class="spec-question__id">Q-ADS</div>
    <div class="spec-question__body">
      <strong>広告を実装するか・しないか</strong>
      <br/>
      LP は「Free: 広告あり / Premium: 非表示」と表記。広告 SDK は未組み込み。そもそも「広告を表示する」前提自体が未確定。
      <br/>
      <em>選択肢:</em> (a) AdMob 等を組み込み Free に表示する / (b) 広告なしモデルに切り替え LP 表記を変える / (c) Sponsored Content 形式（提携店舗紹介）
      <br/>
      <em>注意:</em> 広告ありにする場合、UX 設計（どこに置くか）と Premium の動機付けを同時に決める必要
    </div>
    <div class="spec-question__meta">
      <span class="spec-badge spec-badge--partial">🟡 中</span>
      <span>担当: PO</span>
      <span>状態: 未着手</span>
    </div>
  </div>

  <div class="spec-question" id="q-insurance-tax-notify">
    <div class="spec-question__id">Q-INS-TAX<br/>-NOTIFY</div>
    <div class="spec-question__body">
      <strong>任意保険・自動車税の通知を実装するか</strong>
      <br/>
      LP には記載していないが、リマインダー機能の自然な拡張。通知メソッド自体が無い状態。
      <br/>
      <em>選択肢:</em> (a) 自動車税は毎年 5 月固定なので OS の標準通知でも良い / (b) アプリ独自で柔軟にスケジュール
    </div>
    <div class="spec-question__meta">
      <span class="spec-badge spec-badge--partial">🟡 中</span>
      <span>担当: PO + Designer</span>
      <span>状態: 未着手</span>
    </div>
  </div>

  <div class="spec-question" id="q-reminder-coverage">
    <div class="spec-question__id">Q-REMINDER<br/>-COVERAGE</div>
    <div class="spec-question__body">
      <strong>整備サブカテゴリと reminder.type のカバレッジを揃える</strong>
      <br/>
      整備記録保存時に対応するリマインダーの <code>nextDueDate</code> / <code>nextDueOdometer</code> を更新する仕組み（issue <a href="https://github.com/CreativeCaffeine/carapp/issues/149">#149</a>）を入れたが、<code>Reminder.type</code> のキーは <code>oil / tire / battery / inspection / aircon / shaken / custom</code> の 7 種のみ。整備サブカテゴリのうち「ブレーキ」「ワイパー」「修理」「板金・塗装」「部品・用品購入」「カスタム・パーツ取付」には対応する標準 reminder.type が無く、これらを記録してもリマインダー側は何も更新されない。
      <br/>
      <em>選択肢:</em> (a) 標準 reminder.type を増やす（例: <code>brake</code>, <code>wiper</code>）→ <code>reminder_item_selection_screen.dart</code> のデフォルト reminder 定義と各種マッピング側を拡張 / (b) これらの記録は「リマインダー連動なし」と仕様で明示し、ユーザーが必要なら custom reminder を作る運用にする / (c) サブカテゴリ → reminder.type マッピングを別データとして集中管理（現状はマッピング関数）
      <br/>
      <em>影響:</em> 整備記録のうちリマインダー連動範囲がユーザーに伝わっていない。設定画面側で「リマインダー対応の項目」を視覚的に区別する UX も併せて検討。
    </div>
    <div class="spec-question__meta">
      <span class="spec-badge spec-badge--partial">🟡 中</span>
      <span>担当: PO + Eng</span>
      <span>状態: 未着手</span>
    </div>

## このページの運用ルール

- 課題 ID は `Q-XXX` 形式。仕様書本体や PR からこの ID で参照する
- 「解決済」になったら別セクションに移動、削除はしない（履歴として残す）
- 各個別 specs に新しく書く `## オープン課題` の項目は、ここにも追記する（または逆向き）
- 重複防止のため、追加前に該当 ID 候補で検索する
